## 2. Cosa è stato escluso (e perché)

- **Automazione release**: non ho creato uno script `scripts/release/update-version.sh` per snellire i rilasci futuri (aggiornamento `params.toml` + nuova voce changelog + tag git in un colpo solo). Rimandato — la gestione manuale è ancora accettabile con la cadenza attuale (1 release/mese)
- **Menu principale con voce "Changelog"**: attualmente il changelog è raggiungibile SOLO dal link nel footer (versione linkata). Non aggiunto al menu top per non appesantire la navigation — il changelog è "informazione di servizio", non parte del funnel commerciale principale
- **Rigenerazione PDF per il commit finale**: le modifiche UI (footer + CSS) non toccano i CV MD, quindi i PDF sono già coerenti dopo l'ultimo merge (`6755072`). Non serve rigenerarli
- **Aggiornamento dei tag messages su origin**: i tag CalVer (`v2026.03.001` → `v2026.09.001`) contengono ancora nei loro messages i riferimenti rimossi (Borzacchiello, articoli specifici, aziende, IDEA DB), perché sono stati creati **prima** della richiesta di pulizia. Le GitHub Releases sono state create con note pulite, ma i git tag messages (visibili solo via `git show v<tag>` o pagina `/tags` di GitHub) non lo sono. **Rimandato** — bassa visibilità pubblica; se vuoi coerenza completa vanno riscritti con `git tag -d` + `git push origin :refs/tags/` + ricreare
- **Menu principale con voce "Changelog"**: il changelog resta raggiungibile solo dal link versione nel footer
